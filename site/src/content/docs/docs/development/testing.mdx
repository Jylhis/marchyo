title: Testing
description: How to run and write tests for Marchyo
---

Marchyo's default checks are evaluation tests: they evaluate NixOS configurations and inspect the result without building any system. A handful of reference systems are each evaluated once, and every test is a named predicate over one of them, so `nix flake check` stays fast. Checks that build something run separately as heavy checks.

## Running tests

```bash
just check          # nix flake check --no-build, then statix + deadnix
nix flake check     # also builds the cheap checks
just check-full     # nix flake check, then builds every heavy check

# List the checks
nix eval .#checks.x86_64-linux --apply builtins.attrNames

# Run one reference system's tests
nix build .#checks.x86_64-linux.ref-desktop
```

## Test structure

```
tests/
  default.nix        # Entry point: builds the reference systems, turns predicates into checks
  lib.nix            # The harness, the reference system bases, shared helpers
  lib-tests.nix      # Library function unit tests
  eval/              # One file per feature, auto-discovered
```

- **Reference systems** — `minimal`, `headless`, `headless-dev`, `desktop`, `desktop-shell-off`, `desktop-dictation`, `full` and the graphics layouts pin the defaults for one kind of host. The tweak systems (`desktop-tweaks`, `headless-tweaks-2`, `desktop-off`, …) collect non-default settings from many test files. Each becomes one check, `ref-<name>`, that runs all its predicates and lists every failing one by name.
- **Variants** — `variant-<name>`, a configuration only one test needs.
- **Negative tests** — `eval-assertions` checks that misconfigurations fail the assertion they should.
- **Heavy checks** — `legacyPackages.<system>.heavyChecks`: Hyprland `--verify-config` runs, theme asset builds, the Plymouth theme, the shell wrapper and the installer ISO evaluations. Run with `just check-full`, and weekly in CI.

See `tests/README.md` for the full layout.

## Writing tests

### Module test

A test is a predicate from the evaluated NixOS `config` to `true`, `false`, a failure message, or a list of failure messages. Put it on the reference system that already has the configuration it needs:

```nix
# tests/eval/my-feature.nix
{ lib, ... }:
{
  refs.desktop.eval-my-feature-default = cfg: cfg.services.my-feature.enable;
  refs.headless.eval-my-feature-headless-off = cfg: !cfg.services.my-feature.enable;
}
```

A non-default setting goes on a tweak system, from the same file:

```nix
{ helpers, lib, ... }:
{
  refs.desktop-tweaks.eval-my-feature-port =
    cfg:
    helpers.expect (lib.elem 1234 cfg.networking.firewall.allowedTCPPorts) "port 1234 is not open";

  refConfig.desktop-tweaks.marchyo.myFeature.port = 1234;
}
```

A negative test names the assertion it expects:

```nix
{
  failing.eval-my-feature-needs-port = {
    on = "misconfigured";
    expect = "marchyo.myFeature.port must be set";
  };
  failingConfig.misconfigured.marchyo.myFeature.enable = true;
}
```

Files under `tests/eval/` are auto-discovered, so no registration is needed.

### Library test

Add to `tests/lib-tests.nix`, using the `assertTest` helper from `tests/lib.nix` (`assertTest name assertion message` — fails at evaluation time when the assertion is false):

```nix
test-my-function =
  let
    result = lib.myFunction "input";
  in
  assertTest "my-function" (result == "expected") "Expected myFunction to transform input";
```

## CI pipeline

The GitHub Actions workflow (`.github/workflows/validate.yml`) runs five jobs:

1. **Lint** — `nix fmt -- --ci` on a single Linux runner. Runs on every push and PR.
2. **Check** — `nix flake check --accept-flake-config` on `x86_64-linux`. Runs on every push and PR.
3. **Check (aarch64-linux)** — the same checks on an ARM runner. Runs only on pushes to `main`, the weekly schedule and manual dispatch.
4. **Build** — `nix build .#nixosConfigurations.x86_64.config.system.build.toplevel`. Runs only on pushes to `main`, the weekly schedule and manual dispatch, after lint and check succeed.
5. **Heavy checks** — builds every `legacyPackages.x86_64-linux.heavyChecks` entry. Runs weekly and on manual dispatch.

Lint and check run in parallel. Concurrency groups cancel superseded PR runs automatically. Builds use [Cachix](https://app.cachix.org) (`jylhis` cache).

A separate `.github/workflows/site.yml` workflow is a build-only gate for the website: changes touching `site/**` or `manual/**` run `npm ci`, `npm run check` and `npm run build`. Deployment happens outside GitHub Actions — Cloudflare Workers Builds deploys the site to [marchyo.org](https://marchyo.org) on push to `main`.
