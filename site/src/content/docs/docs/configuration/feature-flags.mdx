---
title: Feature Flags
description: Enable entire stacks of functionality with simple boolean flags
---

Feature flags are the primary way to configure Marchyo. Each flag enables a group of related packages, services, and configurations.

## Available flags

| Option | Default | Description |
|--------|---------|-------------|
| `marchyo.desktop.enable` | `false` | Desktop environment (Hyprland, Wayland, audio, bluetooth, fonts) |
| `marchyo.development.enable` | `false` | Development tools (git, Docker, buildah, gh, virtualization) |
| `marchyo.media.enable` | `false` | Media applications (Spotify, MPV, etc.) |
| `marchyo.office.enable` | `false` | Office applications (Papers document viewer, Obsidian, Xournal++) |
| `marchyo.shell.enable` | `false` (`true` with desktop) | Quickshell desktop shell: bar, launcher, OSD, panels, notifications, lock ([details](/docs/configuration/shell/)) |
| `marchyo.cli.enable` | `true` | Install the `marchyo` user CLI system-wide |
| `marchyo.emacs.enable` | `false` | Emacs daemon with Hyprland integration ([details](/docs/configuration/emacs/)) |

A second group of flags default to `true` and only take effect when `marchyo.desktop.enable` is set. Set one to `false` to opt out of that part of the desktop:

| Option | Description |
|--------|-------------|
| `marchyo.menus.enable` | Power, session and central system menus |
| `marchyo.utilities.enable` | Date/time and battery notifications, `marchyo transcode`, `marchyo share` |
| `marchyo.reminders.enable` | `marchyo reminder` timers and their keybindings |
| `marchyo.screensaver.enable` | Terminal screensaver on idle |

## Cascading defaults

When you enable `marchyo.desktop.enable`, related flags are automatically enabled at a lower priority using `lib.mkDefault`:

```nix
# Enabling desktop...
marchyo.desktop.enable = true;

# ...automatically enables these (you can override them):
# marchyo.office.enable = true;
# marchyo.media.enable = true;
# marchyo.webapps.enable = true;
# marchyo.shell.enable = true;
```

Since these use `lib.mkDefault`, you can override them:

```nix
{
  marchyo.desktop.enable = true;
  marchyo.media.enable = false;   # Disable media despite desktop being on
}
```

## Boot menu

Marchyo sets `boot.loader.timeout` to `0`, so systemd-boot skips the menu and boots the default entry. Hold <kbd>Space</kbd> at power-on to open the menu.

A timeout stored in an EFI variable overrides `boot.loader.timeout`. A host that set one from the menu keeps the menu visible for that many seconds.

This is a default, so a host can choose its own value:

```nix
boot.loader.timeout = 3;
```

## Desktop environment

When `marchyo.desktop.enable = true`, Marchyo configures:

- **Hyprland** — Wayland compositor with pre-configured keybindings and window rules. Press <kbd>SUPER</kbd>+<kbd>K</kbd> for a searchable, on-screen cheat sheet of all active keybindings (toggle with `marchyo.keybindingsHelp.enable`)
- **Audio** — PipeWire with PulseAudio and ALSA compatibility
- **Bluetooth** — Enabled and configured
- **Fonts** — Curated set of fonts including Nerd Fonts
- **Theming** — Jylhis design-system theming across GTK, Qt, terminals, TUIs, and Emacs, with runtime theme switching
- **Desktop shell**: the unified Quickshell shell (bar, launcher, OSD, panels, notifications, lock, and polkit agent; see [Desktop Shell](/docs/configuration/shell/)). `marchyo.shell.enable = false` keeps only hyprlock and hyprpolkitagent, with no bar, OSD or notification daemon
- **Terminal emulator** — Ghostty
- **Default applications** — Configurable via [`marchyo.defaults.*`](/docs/configuration/default-apps/)

## Development tools

When `marchyo.development.enable = true`, Marchyo configures:

- **Git** with Git LFS and GitHub CLI (`gh`)
- **Containers** — rootless Podman (with podman-tui) or Docker, plus Buildah and Skopeo
- **Virtualization** via QEMU/KVM (libvirtd), with virt-manager and virt-viewer
- **Build tools** — GNU Make, CMake, GCC, pkg-config
- **Utilities** — direnv (with nix-direnv), jq, yq, network debugging tools (nmap, tcpdump, netcat)

Marchyo does not install OBS Studio, Kdenlive or lazydocker. To add one, list it in `environment.systemPackages`:

```nix
environment.systemPackages = with pkgs; [ obs-studio lazydocker ];
```

:::note
Shell enhancements are not gated on `development.enable`: fzf, ripgrep, fd, and
zoxide are installed unconditionally on every Marchyo system, and the Starship
prompt is tied to `marchyo.theme.enable` instead.
:::

### Container backend and the `docker` group

The container backend is selectable and defaults to rootless Podman:

| Option | Default | Description |
|--------|---------|-------------|
| `marchyo.development.containers.backend` | `"podman"` | `"podman"` (rootless, `docker`-compatible CLI) or `"docker"` (rootful daemon) |
| `marchyo.development.containers.dockerGroup` | `false` | Add Marchyo users to the root-equivalent `docker` group (Docker backend only) |

The default rootless Podman backend needs no elevated group at all: it is
daemonless, runs in a user namespace, and provides a `docker` compatibility
shim so most workflows keep working unchanged.

To opt into the classic rootful Docker daemon instead:

```nix
marchyo.development.containers.backend = "docker";
```

:::danger
The Docker backend adds the `docker` group, and membership in it is
**equivalent to passwordless root** on the host. The Docker daemon runs as root
and owns its socket, so any process that can reach the socket can start a
container that mounts and writes the whole host filesystem as root.
Supplementary groups are inherited by every process in the user's session, so
granting it exposes root to *all* code the user runs — browsers, editors, AI
agents, npm scripts, build tools — not just Docker.

Marchyo therefore does **not** add users to the `docker` group by default. The
daemon still runs; `sudo docker …` works. Set
`marchyo.development.containers.dockerGroup = true` only if you accept that every
process in the session effectively has root.
:::

### AI coding agent

Pick a default AI coding-agent CLI (installed only when `development.enable` is
on). The chosen CLI is installed and `$AI_AGENT` is set to its command:

| Option | Default | Choices |
|--------|---------|---------|
| `marchyo.defaults.aiAgent` | `null` | `"claude-code"`, `"codex"`, `"opencode"` |

```nix
marchyo.development.enable = true;
marchyo.defaults.aiAgent = "claude-code";  # installs the CLI, $AI_AGENT = "claude"
```
