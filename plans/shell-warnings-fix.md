# Plan: fix the Quickshell startup warnings (timezone + tray icon)

Investigation-backed fix for the two warnings marchyo-shell emits at startup:

```
WARN: Unable to determine system time zone: please check your system configuration.
WARN: Could not load icon "input-keyboard-symbolic" at size QSize(14, 14) from request
```

## Root causes (both verified live on this host)

### 1. Timezone warning — Qt can't map `/etc/localtime` to an IANA name on NixOS

- The message lives in **qtbase** (`libQt6Core.so.6`, `QTzTimeZonePrivate::staticSystemTimeZoneId()`),
  not in Quickshell. It fires when Quickshell's D-Bus services (Networking et al.) convert
  `QDateTime` values with `Qt::LocalTime` spec — confirmed against the running instance's
  `log.qslog` (warning appears next to NetworkManager `LastScan` property updates).
- Qt derives the system zone's IANA name from the `TZ` env var, or by resolving
  `/etc/localtime` against a zoneinfo database. strace shows it only ever probes
  **`/usr/share/zoneinfo`** — which doesn't exist on NixOS, where `/etc/localtime`
  → `/etc/zoneinfo/...` → a `/nix/store/...-tzdata/share/zoneinfo/...` path.
  Offsets still resolve (via `/etc/localtime` contents); only the *name* fails → warning.
- Tested variants (live session, real shell tree):

  | env | result |
  | --- | --- |
  | *(session as-is, `TZ` unset)* | warning |
  | `TZ=Europe/Zurich` | warning (Qt opens `/usr/share/zoneinfo/Europe/Zurich` → ENOENT) |
  | `TZ=UTC` / POSIX TZ string | no warning, but hardcodes the zone — breaks `marchyo.autoTimezone` |
  | **`TZDIR=/etc/zoneinfo`** | **no warning** — Qt opens `/etc/zoneinfo/Europe/Zurich` + `zone.tab` |
  | `TZDIR=/etc/zoneinfo` (no `TZ`) | **no warning** — Qt matches `/etc/localtime` by inode scan |

- `TZDIR=/etc/zoneinfo` is the correct fix: Qt honours `TZDIR`, `/etc/zoneinfo` exists on
  every marchyo host (`modules/nixos/locale.nix` sets `time.timeZone`, which creates it),
  and it follows the *live* symlink — so `automatic-timezoned` (`marchyo.autoTimezone`)
  zone changes work; a baked store tzdata path or `TZ=` value would go stale.

### 2. Tray icon warning — Qt 6 can't use the session's `qt5ct` platform theme

- The `input-keyboard-symbolic` request comes from **fcitx5's StatusNotifierItem**
  (verified via `busctl`: `:1.286` → `IconName = "input-keyboard-symbolic"`), rendered by
  `TrayWidget`'s `IconImage { source: modelData.icon }` → Quickshell's icon image provider
  → `QIcon::fromTheme`. Size 14 = `Style.fontSize`.
- The session env has `QT_QPA_PLATFORMTHEME=qt5ct` (generated by Home Manager's `qt`
  module — stylix auto-enable sets `qtct` + kvantum). `qt5ct` is a **Qt5** platform-theme
  plugin; there is no Qt6 `qt5ct` plugin, so Quickshell (Qt6) falls back to the generic
  Unix theme whose icon theme is `hicolor` — which doesn't ship `input-keyboard-symbolic`.
  Adwaita (which has it, in `symbolic/devices/`) *is* installed and is marchyo's configured
  GTK icon theme (`modules/home/gtk.nix`: `gtk.iconTheme.name = "Adwaita"`).
- Verified: `Quickshell.hasThemeIcon("input-keyboard-symbolic")` is `false` with the
  session env and `true` with `QT_QPA_PLATFORMTHEME=gtk3` (qtbase ships
  `platformthemes/libqgtk3.so` in Quickshell's closure — no new dependency). The `gtk3`
  platform theme reads marchyo-managed GTK settings (`~/.config/gtk-3.0/settings.ini`),
  exactly what the shell should be themed by. Live-session run with both env fixes:
  **both warnings gone**.
- Side benefit: `NotificationPopup`'s `Quickshell.iconPath(appIcon, true)` themed lookups
  (currently silently returning `""` for missing icons) start resolving too.

## Implementation

The shell must not depend on session env quirks (same philosophy as the baked
tool paths: "nothing depends on the session PATH") — so the fixes live in the
wrapper, covering every entry point: the systemd user service, `nix run .#marchyo-shell`,
manual runs, and the `marchyo-shell ipc` self-targeting calls.

### 1. `packages/marchyo-shell/package.nix` — bake both env fixes into the wrapper

Extend the existing `makeWrapper` call:

```nix
    makeWrapper ${lib.getExe quickshell} "$out/bin/marchyo-shell" \
      --add-flags "-p $out/share/marchyo/shell" \
      --set-default TZDIR /etc/zoneinfo \
      --set QT_QPA_PLATFORMTHEME gtk3
```

with a comment block explaining both:

- `TZDIR` is `--set-default` (a user-set `TZDIR` wins) — points Qt's zoneinfo
  database at NixOS's `/etc/zoneinfo` so `/etc/localtime` maps to an IANA name;
  without it Qt probes only `/usr/share/zoneinfo` and warns.
- `QT_QPA_PLATFORMTHEME` is `--set` (must override the session's Qt5-only
  `qt5ct` value, which has no Qt6 plugin) — makes the Qt6 shell read marchyo's
  GTK settings (icon theme "Adwaita" via `modules/home/gtk.nix`), fixing tray
  and notification themed-icon resolution against `hicolor`.
  Rejected alternative: fixing the session-wide `qt.platformTheme` for all Qt
  apps — larger blast radius (would un-theme stylix's kvantum styling), and the
  shell is a marchyo-owned surface that should follow marchyo's GTK config.

### 2. `shell/Justfile` — dev loop mirrors the wrapper env

```make
dev:
    systemctl --user stop marchyo-shell
    TZDIR=/etc/zoneinfo QT_QPA_PLATFORMTHEME=gtk3 quickshell -p .
```

(with a comment noting the vars mirror the wrapper in `package.nix` so the dev
instance behaves like the store shell).

### 3. `shell/README.md` — document the runtime environment

Short subsection under "Development" ("Runtime environment"): the two env vars,
why the wrapper sets them, and that both are harmless on hosts without
`/etc/zoneinfo` (Qt just falls back to today's behaviour).

### 4. Check in `outputs.nix` — build the package and assert the wrapper

Next to the existing `build-plymouth-theme-*` checks (same `mkChecks` block,
Linux-only attrset), add a check that builds `marchyo-shell` and greps the
generated wrapper (build is cheap: stdenvNoCC + wrapper):

```nix
        build-marchyo-shell-wrapper =
          pkgs.runCommand "check-marchyo-shell-wrapper" { }
            ''
              wrapper="${pkgs.marchyo-shell}/bin/marchyo-shell"
              grep -q "TZDIR=/etc/zoneinfo" "$wrapper" \
                || { echo "FAIL: TZDIR missing from marchyo-shell wrapper"; exit 1; }
              grep -qE "QT_QPA_PLATFORMTHEME=\"?gtk3" "$wrapper" \
                || { echo "FAIL: QT_QPA_PLATFORMTHEME=gtk3 missing from marchyo-shell wrapper"; exit 1; }
              touch "$out"
            '';
```

(Exact grep pattern for `--set-default`'s generated `if [ -z "${TZDIR-}" ]` shell
lines to be confirmed against the built wrapper; keep the patterns loose enough
to survive makeWrapper quoting changes.)

### Not changed

- No QML changes — both warnings are environmental, not shell bugs.
- `modules/home/marchyo-shell.nix` needs no `Environment=` entries: the wrapper
  covers the service and every other invocation path.
- No site-docs sync (no `modules/nixos/options/` change; the shell has no site
  docs page yet).
