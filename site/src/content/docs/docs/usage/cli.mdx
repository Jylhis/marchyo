Every marchyo system ships the `marchyo` CLI (`marchyo.cli.enable`, default `true`). It is the single control surface for the desktop: the Hyprland keybindings, the shell bar, and menus all dispatch through it, and you can drive the same actions from any terminal.

## The change model: runtime-first

Every *mutating* desktop command follows one three-mode contract:

- **default = runtime** — the change applies live (hyprctl, systemd user units, symlink swaps) and is recorded as an ephemeral override in `~/.local/state/marchyo/runtime.json`. Instant, no rebuild. Overrides survive compositor restarts and home-manager activations: `marchyo runtime restore` replays them (theme first, then wallpaper, fonts, appearance and toggles) from a Hyprland `exec-once` and after every activation, and never fails the activation. `--apply` or `--revert` drops an override.
- **`--apply`** — additionally persists the change to `/etc/marchyo/cli-state.json` and runs `nixos-rebuild switch`. Survives reboot; hand-written flake configuration still wins (the sidecar merges at `lib.mkDefault` priority).
- **`--revert`** — undoes: drops the runtime override, restores the declarative value live, and deletes + rebuilds any persisted key.

Declarative-only commands (`install`, `remove`, `webapp`) have no runtime leg — they always edit the state file and rebuild. `security enroll` only runs `fprintd-enroll` or `pamu2fcfg`; it never rebuilds.

### Wiring `--apply` into your flake

The marchyo flake never reads absolute paths (evaluation stays pure). To let CLI-persisted settings reach your system, read the sidecar in your own flake:

```nix
# in your flake.nix configuration module
{
  marchyoCliState =
    builtins.fromJSON (builtins.readFile /etc/marchyo/cli-state.json);
}
```

and rebuild with `--impure` (the CLI's own `rebuild` passes it automatically).

## Command reference

### System

| Command | Purpose |
|---------|---------|
| `marchyo status` | Dashboard of current config + system info |
| `marchyo rebuild [-n]` | `nixos-rebuild switch --impure --flake` against the detected flake |
| `marchyo update [-n] [--check]` | `nix flake update` in the detected flake; `--check` only reports whether the lock pins a newer nixpkgs than the running system |
| `marchyo upgrade [-n]` | Update inputs, then rebuild |
| `marchyo rollback [-n]` | Switch to the previous generation |
| `marchyo gc [--delete-older-than 14d]` | Collect Nix garbage |
| `marchyo diff [-n]` | Diff system generations (dix) |
| `marchyo debug` | Diagnostics bundle (versions, generation, journal errors) |
| `marchyo doctor` | Session health checks: PASS/FAIL/SKIP per check (shell baked tool paths exist, Hyprland and shell IPC answer, marchyo user services active); exits `1` on any FAIL |

### Theme & wallpaper

| Command | Purpose |

| `marchyo theme set <name> [--apply\|--revert]` | Live switch (`dark`/`light` alias the Jylhis pair) |
| `marchyo theme next` | Cycle the manifest |
| `marchyo theme gaps [on\|off] [--apply\|--revert]` | Window gaps; `--apply` persists `marchyo.theme.appearance.gaps` |
| `marchyo theme transparency\|corners [mode] [--revert]` | Window transparency and corners (runtime-only) |
| `marchyo theme generate [image] [--light\|--dark] [--revert]` | Build a theme from a wallpaper with matugen and apply it live |
| `marchyo theme bar-position [top\|bottom]` / `theme bar-background [opaque\|glassy\|clear]` | Shell bar placement and background (runtime-only, written to the shell style file) |
| `marchyo bar put <id> <section> [--at N]` / `move <id> left\|right [n]` / `remove <id>` / `set <section> [ids...]` | Edit the shell bar layout live (sections: `left`, `centerBegin`, `center`, `centerEnd`, `right`); recorded in `bar-layout.json` and replayed by `runtime restore` |
| `marchyo bar list` / `bar reset` | Show the recorded edits / drop them |
| `marchyo bar background [mode]` / `bar position [pos]` | Same as `theme bar-background` / `theme bar-position` |
| `marchyo theme icons [name] [--revert]` | List installed icon themes, or set one live (dconf); `--revert` restores `gtk.iconTheme` |
| `marchyo bg set <path>` / `bg next` | Wallpaper set / cycle through `bg list` (runtime-only) |

`theme list --format json` also reports each theme's `preview` (palette card) and `wallpaper` paths when its directory ships them. Shell-side style (reduce motion, UI font, bar position and background) lives in `$XDG_STATE_HOME/marchyo/shell/style.json`, which the shell watches; an absent key means the declarative default.

### Toggles

`marchyo toggle <name> [on|off] [--status|--apply|--revert]` for: `gaps`, `transparency`, `animations`, `reduce-motion`, `fullscreen-desktop`, `nightlight`, `waybar`, `touchpad`, `touchscreen`, `idle`, `screensaver`, `notifications`, `suspend`, and `hybrid-gpu`. `hybrid-gpu` is `--apply`-only: it changes hardware configuration, persisting `marchyo.graphics.prime.enable`. `reduce-motion` also takes `--apply` and persists `marchyo.theme.appearance.reduceMotion`. With the shell enabled, `waybar` and `notifications` `--status` read the live bar/DND state over shell IPC (falling back to the recorded runtime override when the shell is not running).

### Shell

Verbs over the running marchyo shell (`marchyo.shell.enable`), used by hypridle, the screensaver, the lock bind and scripts (the other shell binds use Hyprland global shortcuts). Each call goes through `qs ipc`. Each exits `1` with a hint when `marchyo-shell` is not installed or not running, and prints the shell's reply (`--json`: `{"function", "reply"}`).

| Command | Purpose |
|---------|---------|
| `marchyo shell toggle\|open <panel>` | Toggle or open a panel (`controlcenter`, `audio`, `network`, `power`, `monitor`, `notifications`, …) |
| `marchyo shell close [<panel>]` | Close the named panel when it is open, or whichever panel is open |
| `marchyo shell gallery [section]` | Open the Ui gallery panel (dev): every shell control in every state. Sections: `states`, `buttons`, `inputs`, `choices`, `panel`, `popups`, `dialogs` |
| `marchyo shell launcher <mode>` | Toggle the launcher in a mode (`apps`, `emoji`, `clipboard`) |
| `marchyo shell bar [on\|off]` | Toggle or set the top bar |
| `marchyo shell overview [on\|off]` | Toggle, open (`on`) or close (`off`) the window overview |
| `marchyo shell lock` | Lock with the shell lock screen |
| `marchyo shell lock-state` | Print `locked` or `unlocked` |
| `marchyo shell bar-state` | Print `on` or `off` (the top bar) |
| `marchyo shell dnd-state` | Print `on` or `off` (do-not-disturb) |
| `marchyo shell dismiss [--all]` | Dismiss the newest notification toast (`--all`: every toast) |
| `marchyo shell notify-keys` | Control the notification toasts from the keyboard |
| `marchyo shell dnd [on\|off]` | Toggle or set do-not-disturb |
| `marchyo shell reload` | Reload the shell's QML in place |

### Volume & brightness

| Command | Purpose |
|---------|---------|
| `marchyo volume up\|down\|mute [--mic]` | Step (5%, capped at 100%) or mute the default sink, or the default source with `--mic` |
| `marchyo brightness up\|down` | Step the backlight 5% |

With the shell installed these run silent `wpctl` / `brightnessctl` and the shell OSD shows the level (brightness through an `osdShow` IPC poke). Without it they run plain `wpctl` / `brightnessctl`.

#### Sharing with LocalSend

`marchyo share` speaks the [LocalSend](https://localsend.org) v2 protocol itself, so it sends to phones and computers running LocalSend without opening the app:

- `marchyo share photo.jpg notes/` looks for LocalSend devices on the local network for about 2 seconds. With one device it sends straight away; with several it opens a picker (under `--no-input` it lists them and asks for `--to`). Folders are sent recursively and arrive with their structure.
- `--to <alias|ip>` picks the receiver by its LocalSend name, or by IPv4 address (optionally `ip:port`), which skips discovery. Use it in scripts.
- `--pin <pin>` answers a receiver that asks for a PIN.
- `--clipboard` copies a file's contents (or a folder's path) to the clipboard with `wl-copy` instead of sending.
- With no paths, a gum menu picks a file, a folder, or the current clipboard text (sent as a LocalSend message).
- `--json` prints the result (`{"share": {"peer": …, "status": "sent", "sent": n, "skipped": n}}`).

The receiver has to accept the transfer; desktop notifications report when it is accepted, declined, and finished. Discovery uses UDP multicast on port 53317 and falls back to scanning the local /24 subnet, so sending also works with `programs.localsend.openFirewall = false`. `Share` is also listed under **Trigger** in `marchyo menu`.

### Plumbing

`marchyo runtime status` lists active overrides; `marchyo runtime restore` replays them (wired at session start and after every home-manager activation). `marchyo completion bash|zsh|fish|man` emits completions and the man page — installed with the package.

## Standard flags & conventions

`--format text|json` (or `--json`), `--color`, `--no-color`, `--plain`, `--no-animation`, `--no-input`, `-q`, `-v`. Data goes to stdout, diagnostics to stderr. Exit codes: `0` success, `1` runtime failure, `2` usage error.

**Stability:** as of 1.0, command names, arguments, flags, and exit codes are frozen until 2.0 (additions allowed in 1.x). The state files (`cli-state.json`, `runtime.json`) are internal and may change between minor versions.
