Marchyo has an optional AI setup built in, and it's *bring-your-own-key*: you supply
an API key, and Marchyo wires up the clients, the model routing, and the tooling
around it. It's off until you turn it on, and your key never ends up baked into the
system — it's read from a file at startup, not stored in the build.

The provider is [OpenRouter](https://openrouter.ai), an aggregator that speaks the
OpenAI API and gives you one key for many models. Turning AI on installs a small
coding agent (`pi`) wired to OpenRouter, task-based model routing, and a set of tools
and skills the clients can use.

## Turning it on

Two things: enable AI, and point it at your key. The recommended way to hold the key
is [sops-nix](https://github.com/Mic92/sops-nix), which Marchyo already has wired in —
you declare an encrypted secret and give its path to Marchyo:

```nix
{
  # The desktop user must be able to read the key file, so set the owner —
  # the default secret is root-only and the AI clients couldn't read it.
  sops.secrets."openrouter-api-key".owner = "your-username";

  marchyo.ai = {
    enable = true;
    openrouter.apiKeyFile = config.sops.secrets."openrouter-api-key".path;
  };
}
```

The full sops walkthrough — generating an age key, adding the encrypted file — is in
the AI configuration reference on the site. Any runtime file holding the key works;
sops is just the safe default. Once it's set, rebuild and AI chat is a keystroke away
on `Super + A`.

## The clients

- **pi** — Armin Ronacher's minimal coding agent, wired to OpenRouter for you.
- **claude-code** — installed for convenience, but it talks to Anthropic directly, not
  through OpenRouter. If you want to use it, sign in to it separately.

## Model routing

You rarely want the same model for every job — a quick rename and a hard refactor
have different needs. Marchyo groups work into *buckets* (everyday coding, fast,
reasoning, frontier, summarize, long-context, budget) and points each at a model,
with a fallback chain so that if one model is down or rate-limited, the next takes
over automatically.

The defaults are sensible starting points, and every one is overridable. To point a
bucket at a specific model, or change which bucket the `pi` agent uses:

```nix
marchyo.ai.routing.tasks.frontier.model = "openai/gpt-5.5";
marchyo.ai.routing.tools.pi = "frontier";
```

Model names on OpenRouter change often, so treat the shipped slugs as a baseline and
check them against OpenRouter's live model list.

## Local context and skills

Two extras come along for the ride. **OpenViking** (`marchyo.ai.context.enable`) is a
local context store the agents can draw on — your notes, your skills — kept on your own
machine under `~/.openviking`. And **Agent Skills** (on by default) hand every client a
shared set of reusable instructions, including Marchyo-specific ones for editing your
config and debugging Nix builds. There are also **MCP tools** wired in, most usefully a
NixOS lookup so the agents get real package and option names instead of guessing.

## What isn't here yet

Local, on-device inference (`marchyo.ai.local.enable`) is declared but not implemented
— enabling it stops the build on purpose. For now, everything routes through
OpenRouter.
