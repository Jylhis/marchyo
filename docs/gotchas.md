# Gotchas

The accumulated sharp edges. Read the relevant bullet before touching a themed
surface, the launcher, the boot splash, or the input pinning.

- **Deprecated options**: `marchyo.keyboard.variant` still works but emits a warning (superseded by a per-layout `variant` in `marchyo.keyboard.layouts`); its deprecation note lives in the option description in `modules/nixos/options/keyboard.nix`.
- **Auto-discovery of modules**: Both `modules/nixos/default.nix` and `modules/home/default.nix` use `lib/discover-modules.nix` to import every `.nix` file in the directory plus any subdirectory containing a `default.nix`. Adding a new module is one file — no import-list edit needed. The NixOS module system merges options/config order-independently, so the dropped explicit ordering is safe; reach for `mkBefore`/`mkAfter`/priorities if a specific merge order ever matters.
- **Theme source of truth**: the palette comes from the design tokens vendored in `lib/design` (`pkgs.jylhis-design-src`; design system 6.0, light/dark modes), read by `lib/design/nix/palette.nix` and exposed through `modules/generic/jylhis-palette.nix`. Ghostty, bat and Emacs themes are pre-generated snapshots in `lib/design/platforms/` (packaged as `pkgs.jylhis-themes`); GTK css and starship read the vendored files directly. `lib/design/README.md` says how to refresh them. Only `marchyo.theme.scheme = "<name>"` overrides the palette and points at a tinted-schemes YAML instead.
- **Design system 6.0 (single theme, two modes)**: one `jylhis` theme with light ("Paper", `#f4efe4`) and dark ("Amber", `#0b0b0b`) modes. `accent` is an alias of `link` (ink by day, amber by night); the red signal is `primary` (no base16 slot). The v3 `brand`, `contour` and `decorator` roles are retired; `modules/generic/jylhis-palette.nix` keeps them as aliases (brand → accent, contour → text-muted, decorator → border-strong) so older consumers still evaluate. Syntax colors are literal Modus Operandi/Vivendi values. marchyo reads only `palette`/`status`/`syntax`/`ansi` keys, merged into `palette.hex`. Platform files are committed snapshots: Ghostty, bat and Emacs reach consumers as paths through `pkgs.jylhis-themes`, while GTK css and starship are read as eval-time text (no import-from-derivation).
- **Desktop UI font is Fira Sans; code is IBM Plex Mono**: sansSerif = **Fira Sans** (`pkgs.fira-sans`), serif = DejaVu Serif, monospace = **IBM Plex Mono** (`pkgs.ibm-plex`); `pkgs.jost` (the web display face) is installed too. Family names come from the design system (`lib/design/nix/fonts.nix`, via `pkgs.jylhis-design-src`). The shell, greeter, hyprlock, Ghostty and the Emacs fixed face need the icon glyphs, so they ask for `"BlexMono Nerd Font"` (`pkgs.nerd-fonts.blex-mono`, IBM Plex Mono patched) directly (`modules/home/{hyprlock,ghostty}.nix`); keep those in step with this mapping. The role mapping lives in `modules/nixos/fonts.nix` (system level, so the greeter sees it); the GNOME interface fonts in `modules/home/jylhis-theme.nix`.
- **fontconfig's per-user cache can outlive a generation**: HM scans `~/.nix-profile/share/fonts` (`~/.config/fontconfig/conf.d/10-hm-fonts.conf`), and the cache under `~/.cache/fontconfig` keeps serving entries for fonts that left the profile. Apps then resolve the role-mapped families above to dead store/profile paths and fall back with mismatched metrics — Chrome logs `Could not find any font: <family>, sans. Falling back to the default` and paints bookmarks/tab text vertically offset and clipped. `modules/home/fontconfig-cache.nix` hashes the profile font set at every activation and rebuilds the cache when it changes (`marchyo.fonts.cleanUserCache`, default on). A running app keeps its in-process fallback until restarted.
- **Stylix is retired**: marchyo owns every themed surface itself (no stylix input, no stylix modules). The former long-tail targets are re-homed: base16-slot surfaces (lazygit, k9s, spotify-player, gdu) theme from `modules/generic/theme-slots.nix`, Emacs loads the design system's own jylhis themes, Qt follows the live GTK surface (`QT_QPA_PLATFORMTHEME=gtk3`, `modules/home/qt.nix`), and the GNOME interface fonts + cursor live in `modules/home/jylhis-theme.nix`. `aerc` ships its own styleset because the base16 convention (base07 as foreground) renders white-on-white in the light variant; `modules/home/aerc.nix`.
- **Plymouth splash is generated, not baked**: `packages/plymouth-marchyo-theme/` ships no wordmark/progress PNG assets. The splash is animated (v5): a "❯" caret (`caret.svg`, accent-tinted) sweeps a wordmark on and off screen, alternating between "marchyo" and "jylhis", with a blinking prompt-style rest, sparkle particles trailing the caret tip, and a burst when a word lands — see `marchyo.script`. Plymouth has no clipping, so the reveal is a bg-colored `cover.png` sprite sliding over the word. At build time `package.nix` (a) rasterizes `logo.svg` into `marchyo.png` and renders `jylhis.png` in JetBrains Mono Bold at the same cap height, (b) tints `caret.svg` and renders `sparkle.svg` in three syntax-palette tints (`syn-function`/`syn-keyword`/`syn-type` → `sparkle1-3.png`), (c) generates the solid `cover.png`/`progress_bar`/`progress_box`, and (d) recolors the omarchy chrome PNG images (`entry`/`lock`/`bullet`) with ImageMagick — all colored from the design palette (`lib/design/nix/palette.nix`) for the selected `variant` (dark = Jylhis Dark, light = Jylhis Light). The "marchyo" wordmark is the omarchy logo (`basecamp/omarchy` `logo.svg`, seven pixel-art letter paths) with the leading `o` moved to the end. That reorder is done by drawing the letter group twice inside the fixed `1215x285` viewBox and letting the SVG clip (copy A shifted `-165u` reads "marchy"; copy B shifted `+1080u` drops the `o` into the trailing slot). `modules/nixos/plymouth.nix` passes `marchyo.theme.variant` via `.override { variant = …; }`, so a variant flip retints the whole splash. Because plymouth runs at boot, the variant is baked at build (there is no runtime switch; the baked variant is exposed as `passthru.variant` for tests). `pkgs.plymouth-marchyo-theme` (overlay) defaults to `dark`. Validation: the package's `installCheckPhase` verifies every `Image()` the script references exists, no `@…@` placeholder survives, and the cover mask is pixel-identical to the bg token; `tests/eval/plymouth.nix` covers the NixOS wiring; the `build-plymouth-theme-{dark,light}` heavy checks build both variants.
- **`disko/` and `installer/` are flake outputs**: each `disko/<layout>.nix` is a function of its disk(s) exposed as `lib.diskoLayout "<layout>" { device = …; }` (raid1 takes `deviceA`/`deviceB`), imported next to `nixosModules.disko`. There are deliberately no `diskoConfigurations` with example devices: `disko --flake` on one would wipe whatever disk the example names. Partition through the host's own `nixosConfigurations.<host>`. The ISOs are `packages.x86_64-linux.iso-{minimal,graphical}` (`just iso <variant>`). `tests/eval/disko.nix` evaluates every layout on a dummy disk, `nix flake check` evaluates the `iso-*` packages, and the `eval-iso-*` heavy checks force each ISO's drvPath, so neither rots unnoticed.
- **`allowUnfree = true`**: Set globally in `legacyPackages` (via `outputs.nix`) and in test configs.
- **Formatter runs multiple tools**: `nix fmt` runs nixfmt, deadnix (unused vars), statix (linting), shellcheck, and yamlfmt via treefmt-nix (`treefmt.nix`). All must pass.
- **Nixpkgs pin sync**: `flake.lock` is the source of truth for all flake inputs. The devenv dev shell mirrors only the primary (unstable) `nixpkgs` and `treefmt-nix`; the other inputs are flake-only. Run `just update` to bump inputs and sync `devenv.lock` to the same `nixpkgs` rev (`nix flake update` → extract rev → update `devenv.yaml` → `devenv update`). Run `just verify` to check the mirrored inputs are aligned. Dependabot bumps `flake.lock` independently (its `nix` ecosystem group) but does not update `devenv.lock` — CI's `verify` job catches this drift so the PR will fail until `just update` is run to re-sync.
- **Home Manager modules need the NixOS module**: `modules/home/*` read `osConfig.marchyo.*` directly, with no `or` fallbacks, so the declared NixOS option is the only default. There is no standalone Home Manager output and no test evaluates `homeManagerModules` in isolation. Keep `or` only for lookups that may genuinely miss (attrsOf entries, user-supplied packages or attrsets), with a comment.
- **GPU driver variables follow `marchyo.graphics.primary`, in one place**: `modules/nixos/graphics.nix` sets `LIBVA_DRIVER_NAME`, `VDPAU_DRIVER`, NVIDIA's GLX/GBM variables and `AQ_DRM_DEVICES` as NixOS session variables for the primary GPU only; Home Manager's Hyprland env must not repeat them (it used to, and overrode the NixOS logic). `AQ_DRM_DEVICES` points at the `/dev/dri/marchyo-<vendor>` udev symlinks: aquamarine splits the list on `:`, so `/dev/dri/by-path/pci-0000:…` names cannot go in it, and `/dev/dri/card<N>` numbering is not stable.
- **Shared treefmt config**: `treefmt.nix` is the single source of truth for formatting. Both the flake formatter (`nix fmt`) and the devenv shell (`treefmt`) use it. devenv.yaml includes `treefmt-nix` as an input for this purpose.
- **Bash is the default login shell**: NixOS sets `users.defaultUserShell = bashInteractive` (mkDefault, `modules/nixos/system.nix`); bash is the only shell configured (zsh/fish were removed).
- **Ghostty `ssh-env`/`ssh-terminfo` are deliberately enabled**: these shell-integration features are opt-in upstream (off by default). `modules/home/ghostty.nix` sets `shell-integration-features = "no-title,ssh-env,ssh-terminfo"` so SSH from Ghostty installs the xterm-ghostty terminfo on the remote (or falls back to `TERM=xterm-256color`) — don't "simplify" back to `no-title`; that breaks TUI apps over SSH. Inbound SSH is covered by `pkgs.ghostty.terminfo` in NixOS systemPackages (`modules/nixos/system.nix`).
- **Nixpkgs passthrough**: Flake inputs use `follows = "nixpkgs"` (the unstable primary) where they take a nixpkgs. Consumers should build via `marchyo.lib.mkNixosSystem`, which brings marchyo's nixpkgs; `marchyo.legacyPackages.<system>` is the overlay-applied package set. The workstation template demonstrates the builder pattern.
- **`site/`**: The Astro + Starlight website (landing page + docs), built with bun (in the dev shell) and deployed to Cloudflare Workers at https://marchyo.org. `just site-dev` / `just site-build` are the local entry points. Option documentation in `site/src/content/docs/docs/configuration/` should be kept in sync with the option declarations under `modules/nixos/options/`.
- **hyprlock fingerprint auth is gated on fprintd**: `modules/home/hyprlock.nix` sets `auth."fingerprint:enabled" = osConfig.services.fprintd.enable`, not a hardcoded `true`. hyprlock's fprintd D-Bus backend aborts the process when the service is absent, so hardcoding it on breaks the lock screen on any desktop without a fingerprint reader — and marchyo never enables `services.fprintd` itself. A host that wants fingerprint unlock enables `services.fprintd` (e.g. via `nixos-hardware`) and the setting follows automatically. Don't "simplify" it back to `true`.
- **The in-shell launcher pastes via wtype after a settle, not uinput**: `Services/Launcher.pasteText` copies with `Quickshell.clipboardText`, closes the launcher, sleeps 0.25 s, then runs `wtype`. wtype delivers to whatever surface holds keyboard focus *when it runs* — which is the launcher while open, hence close-first. If a host ever sees pastes landing nowhere (slow compositor refocus), raise the sleep; don't "fix" it by typing while the launcher is still open. Nothing writes `/dev/uinput`.
- **Launcher emoji rows are generated in the package build, never at eval**: `packages/marchyo-shell/emoji.awk` + the installPhase splice regenerate `Commons/EmojiData.js`'s RAW rows from `pkgs.unicode-emoji`'s emoji-test.txt. The splice greps the marker text verbatim, so nothing else in that file may spell `BEGIN-GENERATED`/`END-GENERATED` (the header comment deliberately doesn't). A broken generator fails the derivation's `count < 1000` guard rather than shipping a stub catalog. This is the same no-IFD rule as the `tinted-schemes` input: parsing at eval time would force a package build in `nix flake check`.
- **The launcher binds are gated on `marchyo.launcher.enable` and `marchyo.shell.enable`**: `modules/home/hyprland.nix` wires SUPER+R / SUPER+period / SUPER+Ctrl+V only when both are on, so no host gets a dead bind.
- **iwd backend Wi-Fi crashes**: NetworkManager stays on its default wpa_supplicant backend; `modules/nixos/network.nix` deliberately leaves `networking.networkmanager.wifi.backend` unset. With `"iwd"`, iwd 3.12 segfaults while roaming (in `network_info_get_roam_frequencies`, reached through an 802.11k neighbor report) on multi-AP networks, so the connection drops over and over. Don't switch the backend to iwd until that is fixed upstream; a host that wants iwd anyway can set it itself.
